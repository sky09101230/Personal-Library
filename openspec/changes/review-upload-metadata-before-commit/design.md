## Context

### 2026-09-28 历史规范对齐

本 Change 的发布规则承接 `batch-upload-supplementary-materials`：旧 Change 先归档，再归档本 Change；不能逆序归档而恢复未经确认的 Browser/MCP 发布。本 Change 保留原 Requirement/Scenario 标识并更新前置条件，完整承接 supplementary 从属可见性场景；“上传成功”对 Browser/MCP 指完成上传者确认和正式登记，不是仅写入暂存对象。未完成的任务和实际验收状态不因本次规范修复而改变。

网页上传已经通过 `UploadReviewBatch` / `UploadReviewItem` 完成 PDF 暂存、metadata 审核和确认后入库，MCP 上传仍会直接创建正式文献并发布。文件可能达到 100 MB，确认页面不能要求客户端再次上传；同时正式库、Library 和 MCP 检索都以 `CanonicalDocument` / `UploadedDocument` 为边界。

## Goals / Non-Goals

**Goals:**
- 文件只传输到 NAS 一次，确认后直接复用已存远端路径。
- 暂存批次严格归属上传者，正式表在确认前零写入。
- Browser 与 MCP 复用同一暂存、解析、确认和取消应用层逻辑。
- 保留现有 DOI 解析、去重、确认后发布和最多四通道浏览器上传约束。

**Non-Goals:**
- 不改变 Zotero 或管理员 AI metadata 审核流程。
- 不增加后台队列、定时清理器或新的外部依赖。
- 不重新启用补充材料自动识别。
- 不为 MCP 新增 metadata 编辑接口或新的发布权限。

## Decisions

1. 新增最小的 `UploadReviewBatch` 与 `UploadReviewItem` 暂存模型。批次保存上传者和状态；文件项保存 NAS 路径、摘要及结构化 metadata。相比把 100 MB 文件留在进程缓存或签名 cookie，数据库暂存可跨请求、跨进程且能追踪待清理对象；它不属于正式文献表，也不被 Library/MCP 查询。
2. 请求无关的薄应用层函数负责创建批次、暂存 PDF、重新解析、确认和取消；Browser 视图只负责登录态、对象归属与 HTTP 转换，MCP 工具只负责令牌身份、Base64 和结果文本转换。这样两个入口共享正式数据库边界而不增加重复 API。
3. 浏览器先创建空批次，再由四个固定 worker 各自上传一个文件。MCP 每次调用创建一个单文件批次，使用访问令牌 `client_id` 中的 `user:<id>` 作为 uploader，暂存完成后立即返回，不等待网页确认。
4. 初始解析与 DOI 重解析复用现有 PDF evidence、DOI 选择、BibTeX 获取与解析函数。暂存阶段直接生成字段字典，不创建临时 `CanonicalDocument`；确认时把已核对字段复制到正式记录。
5. 缺标题是阻断错误；缺期刊以及 DOI/BibTeX 标题与 PDF 提取标题明显不一致是黄色 warning，均允许上传者明确确认。标题差异复用现有规范化相似度判断，且只在两端标题都存在时产生 warning。
6. 确认操作在单个数据库事务内逐项执行既有 DOI/SHA 去重语义。新文件直接以暂存 NAS 路径创建正式上传记录，不再次 PUT；已有正文则删除多余暂存对象并关联上传者。数据库失败时不删除暂存对象，以便重试。
7. 取消操作逐项删除 NAS 对象，删除成功后才删除暂存记录。暂不增加自动过期任务；需要定时清理时再基于实际遗留量增加管理命令。
8. MCP 返回的审核 URL 指向现有上传页面并携带 batch ID。页面仅在当前登录用户拥有该 pending batch 时恢复条目；其他用户得到 404，不暴露文件名或 metadata。
9. 四个通道和 metadata 表格使用紧凑的原生 CSS 布局，长文件名最多显示两行并保留悬停全文。全部上传 worker 完成后浏览器滚动到审核区；确认接口成功后直接进入 Library，不增加中间成功页或新的后端状态。

## Risks / Trade-offs

- [用户关闭页面会留下待确认批次] → 保留可追踪暂存行与取消接口；先观察遗留量，再决定是否需要自动清理。
- [确认重复文献时需要删除刚上传的冗余对象] → 删除失败则保留暂存项并中止确认，避免不可追踪孤儿文件。
- [外部 DOI 服务慢] → 每个文件独立请求且浏览器最多四并发，其他通道继续推进并显示服务端解析阶段。
- [MCP 令牌所属用户与网页登录用户不一致] → 审核页继续按 batch uploader 做 404 级对象权限校验，必须登录同一账户才能查看或操作。
- [工作树已有上传与补充材料修改] → 只修改网页主文献路径，并保持补充材料自动识别关闭。

## Migration Plan

1. 添加仅包含暂存批次与文件项的新迁移，不回填既有数据。
2. 部署模型、端点和页面后，新的网页上传进入确认流程；现有正式文献不变。
3. 回滚前先处理未确认批次；代码回滚后可删除新增暂存表，NAS 中已确认正式文件不受影响。
