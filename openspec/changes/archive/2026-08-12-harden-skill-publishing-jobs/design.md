## Context

网页已改为 GitHub 候选扫描，但旧 management command 仍能直接发布。元数据补全会克隆最新 HEAD。任务由独立进程运行，创建时先查后写，没有数据库唯一约束或过期恢复。

## Goals / Non-Goals

**Goals:**
- 删除无人使用的旧直发布链路。
- 从 NAS 正式 Release 读取 `SKILL.md` 做元数据补全。
- 用数据库约束和一个活动时间字段处理并发与卡死。

**Non-Goals:**
- 不引入 Celery、Redis、消息队列或进程守护器。
- 不改变候选 ZIP 校验和人工审核页面。
- 不修改邀请码、账号或 NAS TLS。

## Decisions

### 删除旧直发布代码

旧入口只有 management command 和旧测试调用，网页没有消费者。直接删除比保留隐藏开关更小，也避免日后误用。

### 检出最新正式 Release 的提交

每个 GitHub 来源只克隆一次完整仓库。按 Skill 查询最新 Release，逐个检出其 `git_commit`，从记录的 `source_path` 读取 `SKILL.md` 后调用现有 DeepSeek 补全。这样元数据严格对齐已发布版本，同时继续与 NAS 归档存储解耦。

### 条件唯一约束加活动时间

在任务状态为 `queued` 或 `running` 时，以固定字段值建立数据库条件唯一约束，阻止并发创建第二条活动任务。新增 `heartbeat_at`，任务开始和进度保存时更新。创建任务的事务先锁住活动任务，把超时项标为失败，再尝试创建；唯一约束冲突时读取已有任务。

默认过期时间固定为一小时，通过一个环境变量留校准入口。当前任务规模下足够；若单步外部调用未来可能超过一小时，再提高时限或换受监督任务服务。

## Risks / Trade-offs

- [进程在一次长调用中超过时限] → Git、WebDAV、DeepSeek 已各有超时；保留环境变量调高总时限。
- [远端 Git 仓库已删除已发布提交] → 当前来源记为失败，不使用未审核 HEAD 兜底。
- [Windows 独立进程仍无系统级自启] → 本次只保证数据库状态可恢复；服务监督留给部署阶段。

## Migration Plan

1. 应用任务字段和条件唯一约束迁移；迁移前把多余活动任务标为失败，只保留最新一条。
2. 部署代码并运行现有 scan/enrichment 测试。
3. 回滚时可保留新增字段和约束；旧命令不会自动恢复。
