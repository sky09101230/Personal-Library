## Context

网页上传当前在预检阶段提取 PDF DOI、标题及页面文本。多 DOI 选择已经比较标题相似度；未提交的实现还记录出版容器并尝试用首页文本替换生成标题。补充材料角色和历史记录已经存在，不能因停用自动识别而删除。

## Goals / Non-Goals

**Goals:**

- 在共享 metadata 提取和 DOI 选择函数中一次性消除两类误识别。
- 只关闭新网页上传的补充材料自动分类，保留历史数据的读取语义。
- 用针对实际故障的回归测试证明行为。

**Non-Goals:**

- 不设计新的补充材料识别算法、人工选择界面或后台关联流程。
- 不修改 MCP、Zotero 上传语义，不迁移或删除历史附件。
- 不引入 DOI 类型外部 API、AI、OCR 或新依赖。

## Decisions

### 在现有 BibTeX 候选比较中使用出版容器

沿用已解析的 BibTeX `journal`/会议容器信息作为同名候选的判别证据，不增加外部请求。标题仍是必要匹配条件；出版容器只解决标题同样匹配时论文与数据集的歧义。

### 在提取入口清空生成标题

识别到 `untitled` 等占位符后先将标题设为空，再尝试首页标题提取。这样即使提取失败，占位符也无法进入后续冲突检测或规范字段合并。相比在每个下游调用点跳过占位符，该处理覆盖网页、MCP 和 metadata 重试路径且改动更小。

### 从网页上传入口移除自动角色分类

新网页上传固定使用正文角色，不调用关键词分类函数。保留模型角色、历史补充附件展示及正文优先下载逻辑，避免数据迁移并为未来重新设计识别规则留下兼容性。

## Risks / Trade-offs

- [真实补充材料暂时按正文处理或因 DOI 去重被跳过] → 这是关闭自动识别的预期限制；待新的识别或人工指定方案单独设计。
- [出版物与数据集标题不完全相同] → 仍以既有标题阈值为边界，避免仅凭存在期刊字段选择无关 DOI。
- [首页文本不可提取] → 保持标题为空并进入待补全流程，不再制造错误冲突。

## Migration Plan

1. 部署 metadata 与网页上传逻辑及回归测试，无数据库迁移。
2. 只读验证两条已人工修正记录仍分别指向 `10.1126/sciadv.adt2187` 和 `10.1038/srep03347`，且期刊字段存在。
3. 回滚时恢复应用代码即可；历史文件角色与记录不变。
