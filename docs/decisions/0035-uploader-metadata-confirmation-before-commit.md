# 0035 上传者确认 metadata 后再写正式文献表

## 决策

Browser 与 MCP 上传共用暂存与确认两个阶段。PDF 只上传一次到 NAS；系统把远端路径、文件摘要和解析结果写入上传者私有的暂存批次，不创建 `CanonicalDocument` 或 `UploadedDocument`。MCP 令牌的 `user:<id>` 映射为批次上传者；MCP 立即返回解析摘要和现有网页审核地址，不等待确认。上传者在上传页修正标题或 DOI 并确认后，系统才在单个事务中创建或关联正式文献记录并发布。

缺少标题是阻断错误。缺少期刊以及 DOI/BibTeX 标题与 PDF 提取标题明显不一致显示为黄色警告，但允许上传者明确确认。暂存批次不进入 Library、MCP 或管理员 metadata 审核队列；网页仍按 batch uploader 严格校验归属。

## 理由

文献身份最可靠的人工核对者是上传者，而不是事后面对陌生论文的管理员。大文件不能为审核重复上传，也不能只保存在单个 Web 进程内；专用暂存表能跨请求追踪 NAS 对象，并把“待确认解析结果”和“正式共享文献”保持为两个明确边界。请求无关的薄应用层函数让 Browser 与 MCP 共享这条边界，无需为 MCP 再造 metadata 编辑 API。

暂不增加自动过期任务。上传者可以取消批次并清理 NAS 对象；待观察实际遗留量后再决定是否需要定时清理，避免提前引入后台调度复杂度。
