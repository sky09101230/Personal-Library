# 0024 Skill 候选审核边界

## 决策

所有用户 ZIP 投稿和 GitHub 仓库扫描结果先进入独立的 `SkillCandidate` 候选池。候选快照存放在 `NAS_WEBDAV_SKILL_CANDIDATES_ROOT`，不创建 `SharedSkill` 或 `SharedSkillRelease`，因此不会进入正式列表、下载接口或 MCP Agent 上下文。

只有管理员批准候选时，系统才把已审核快照复制到 `NAS_WEBDAV_SKILLS_ROOT` 并原子创建正式 Skill 与发布记录。拒绝和成功发布后清理私有候选快照，保留来源、内容指纹、AI 元数据和审核结论。

## 来源与审核

- 普通研究者上传一个仅包含单个 Skill 的 ZIP，不需要使用 GitHub。
- GitHub 来源只扫描候选清单，网页入口不再整仓直接发布。
- DeepSeek 只生成两句中文摘要并从现有叶子分类中选择；失败时保留候选供人工处理。
- 管理员手工确认的分类不会被后续扫描或 AI 结果覆盖。

## 安全边界

ZIP 在上传 NAS 前使用标准库检查大小、成员数、总解压体积、路径穿越、符号链接、加密成员和禁止资产。论文、实验数据、数据库、向量索引、模型权重、私钥、`.env` 和疑似访问令牌不得进入 Skill 候选或正式发布包。候选内容永不执行。

## 分类

分类树以科研任务而非仓库或学科为主轴：文献与知识、数据分析与可视化、建模仿真与机器学习、实验仪器与硬件、科研写作与成果表达、科研工作流与工具集成。现有文献检索和文献阅读记录原地成为“文献与知识”的子分类。
