# 0029 Skill 发布完整性与后台任务恢复

## 决策

GitHub Skill 只通过候选扫描、管理员审核和候选快照发布进入正式库；删除旧的 GitHub 直接发布命令。正式 Skill 的摘要和分类按最新正式 Release 记录的 Git commit 读取 `SKILL.md`，不得使用尚未审核的仓库 HEAD。

后台扫描和补全继续使用独立 Django management command 进程，不引入 Redis、Celery 或新的常驻服务。数据库保证全系统最多一个 `queued` 或 `running` 的 Skill 后台任务，并记录最近活动时间；新请求可以把超过时限而无活动的旧任务标记为失败。

## 边界

该恢复机制解决数据库中的卡死状态和并发创建，不负责操作系统级进程守护、开机自启或自动重试。当前单机低并发部署足够；需要并行任务时再引入受监督的任务队列。
