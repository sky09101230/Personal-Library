# 0014 文献对象存储迁移至 NAS WebDAV

## 决策

新上传文献默认写入 NAS 的 `/public/PLAB_KnowledgeBase/Literature/`。文献记录保存 `storage_backend` 与远端路径，读取和删除均按记录路由；已有记录迁移后标记为 `nju_box`，继续使用保留的 NJU Box 适配器。

网页和 MCP 共用文献存储接口。MCP 仅为已发布文献生成短时、签名的应用下载链接，下载时再次检查发布状态，再由服务端代理对应存储后端的文件。

## 理由

对象位置属于每条记录的事实，不能由当前全局默认值反推。记录级路由允许新旧后端共存，也避免切换默认值后让已有 NJU Box 路径被误读为 NAS 路径。

## 约束

- WebDAV 仅接受 HTTPS origin，但按用户决定，NAS WebDAV 适配器固定跳过证书链和主机名验证；该例外不得扩展到 NJU Box 或其他 HTTPS 客户端。
- NAS 凭据只通过服务端环境变量提供，不进入仓库、网页表单、日志或 MCP 响应。
- Skills 的 NJU Box 镜像流程不在本次迁移范围内。
- 不自动搬迁或删除 NJU Box 既有对象；是否迁移测试数据另行决定。
- PostgreSQL 部署和备份策略不在本次对象存储变更范围内。

## 部署验证

2026-08-09 从开发主机使用初始严格校验版本连接当前 NAS 地址时，TLS 握手因无法验证 Synology 私有签发链而停止，未发送 PUT、未创建测试对象。只读证书检查还显示证书 SAN 仅包含 `synology`，不包含当前访问所用 IP。

经用户明确授权后，使用跳过证书校验的诊断完成了随机测试对象的 PUT、GET 内容比对和 DELETE，三步均成功，测试对象已删除。这确认当前地址、WebDAV 服务、管理员凭据以及 `Literature/` 的读写删除权限有效。随后用户决定正式 NAS WebDAV 请求继续跳过证书验证；该决定保留 HTTPS 加密，但明确接受无法验证 NAS 身份和可能遭受中间人攻击的风险。
