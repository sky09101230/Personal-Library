# PLAB 科研 Agent 系统宏观架构

## 一、系统定位

PLAB 科研 Agent 是课题组内部的：

> **科研知识沉淀平台 + 科研内容检索平台 + 科研工具共享平台 + 智能科研助手**

它主要解决四类问题：

1. 文献数量多、分散，难以检索和复用。
2. 前人的公式推导、研究笔记和代码难以传承。
3. 重复科研任务缺少统一工具，成员各自重复开发。
4. 新成员难以快速了解课题组已有知识和工作方法。

---

## 二、系统整体结构

系统宏观上分成五个中心：

```text
PLAB 科研 Agent
├── 科研知识中心
├── 智能检索与 Agent 中心
├── 科研 Skill 中心
├── 用户协作中心
└── 系统管理中心
```

底层由四类基础设施支撑：

```text
基础设施
├── NJU Box：科研文件与知识内容存储
├── 业务数据库：用户、状态、权限和记录
├── 检索索引：全文和语义检索
└── 模型服务：摘要、整理、检索增强和问答
```

---

# 三、科研知识中心

科研知识中心负责统一接收、整理和管理课题组产生的科研内容。

第一阶段包含四类科研对象：

```text
科研知识对象
├── 文献
├── 公式推导与研究笔记
├── 科研代码与脚本
└── 科研 Skill
```

后续可以扩展：

```text
├── 实验记录
├── 实验数据
├── 仪器操作流程
├── 项目资料
├── 会议记录
└── 研究成果
```

## 1. 文献

系统负责：

* 上传和保存 PDF
* 提取标题、作者、期刊、年份、DOI
* 生成中文摘要
* 提取研究问题、方法和主要结果
* 自动生成标签
* 切分全文并建立检索索引
* 支持上传者审核和修改
* 提供原始 PDF 和引用信息

## 2. 公式推导与研究笔记

系统负责：

* 接收 PDF、Word、LaTeX、图片等格式
* AI 整理为 Markdown
* 规范章节、公式和符号
* 标记疑似错误或不一致
* 保留原始资料和整理版本
* 支持按标题、问题描述、正文和公式检索

## 3. 科研代码与脚本

系统负责：

* 保存 Python、MATLAB、Notebook 等内容
* 自动提取功能说明和依赖
* 记录作者、版本和适用场景
* 支持代码查看和下载
* 支持按文件名、功能、依赖和代码内容检索

## 4. 科研 Skill

系统负责：

* 管理 Codex 可读取的 Skill
* 支持个人 Skill 开发
* 支持提交课题组共享申请
* 管理审核、版本、下载和停用
* 提供输入、输出、依赖和使用示例
* 支持 Python、MATLAB、Prompt 和混合工作流

# 四、智能检索与 Agent 中心

该中心是系统面向普通成员的主要入口。

用户不需要理解目录、数据库或向量索引，只需要用自然语言描述自己的需求。

例如：

```text
查找使用深度学习处理拉曼光谱的文献

有没有人推导过某种边界条件下的扩散方程？

课题组中是否有处理基线漂移的 MATLAB 代码？

总结这篇论文的研究方法和主要结果
```

## 1. 用户意图识别

系统首先判断用户想做什么：

```text
自然语言输入
├── 查找资料
├── 总结指定内容
├── 回答科研问题
├── 对比多篇文献
└── 查找代码或 Skill
```

## 2. 检索体系

检索分为两层：

```text
基础检索
├── 标题
├── 作者
├── 标签
├── 摘要
├── 正文
└── 公式或代码

语义检索
├── 中文问题检索英文内容
├── 英文问题检索中文内容
├── 相似研究问题
└── 相似方法和结果
```

## 3. Agent 回答原则

Agent 只能使用已发布、用户有权访问的内容。

回答分为三种情况：

```text
证据充足
→ 给出结论和来源

证据不足
→ 不强行回答，展示相关资料

资料结论冲突
→ 分别说明不同结论和适用条件
```

Agent 必须提供：

* 使用了哪些文献或知识条目
* 原始文件链接
* 必要时提供章节或页码
* 对不确定内容明确标记

# 五、科研 Skill 中心

科研 Skill 中心负责把成员个人的重复性科研工作沉淀为可共享能力。

Skill 可以是：

```text
固定 Prompt
可执行 Python 脚本
MATLAB 程序
文件模板
数据处理流程
多步骤科研工作流
```

## Skill 生命周期

```text
个人创建
→ 个人测试
→ 提交共享
→ 管理员审核
→ 发布课题组版本
→ 成员下载使用
→ 提交问题反馈
→ 发布新版本或弃用
```

## Skill 分层

```text
个人 Skill
仅作者使用

待审核 Skill
申请共享，等待管理员审核

共享 Skill
课题组成员均可下载

已弃用 Skill
保留历史，用于复现旧工作

已停用 Skill
存在安全或严重错误，禁止下载
```

Skill 中心主要解决：

* 每个人重复开发相同工具
* 工具缺少说明
* 工具依赖和环境不清晰
* 工具版本不可追溯
* 作者离组后工具无人维护

---

# 六、用户协作中心

系统面向约 20 名课题组成员。

## 用户角色

```text
管理员
├── 管理成员和权限
├── 管理邀请码
├── 审核共享 Skill
├── 管理所有内容
├── 查看任务和日志
└── 控制系统模块

普通成员
├── 上传资料
├── 审核自己上传的内容
├── 发布和修改自己的内容
├── 检索知识库
├── 使用 Agent
└── 下载共享 Skill

开发协作者
├── 维护系统代码
├── 处理反馈
└── 协助排查任务问题
```

## 内容责任制

系统采用：

> **谁上传，谁负责初次审核和维护。**

管理员可以：

* 修改任意内容
* 停用问题内容
* 转交维护权
* 恢复或彻底删除内容

# 七、系统管理中心

系统管理中心用于保证平台长期稳定运行。

主要包含：

```text
系统管理
├── 用户与邀请码
├── 权限管理
├── 内容管理
├── 任务队列
├── 模型状态
├── 失败任务
├── 模块开关
├── 操作日志
├── 搜索记录
├── 反馈管理
└── 系统配置
```

管理员可以独立关闭：

* 文献上传
* AI 摘要
* 自然语言检索
* Agent 问答
* 公式笔记上传
* 代码上传
* Skill 上传或下载
* GitHub 同步

这样某个模块发生问题时，不必停止整个系统。

# 八、数据与基础设施层

## 1. NJU Box：科研内容主存储

NJU Box 负责保存文件类内容：

```text
NJU Box
├── 原始文献 PDF
├── Word、LaTeX 和笔记图片
├── Python 和 MATLAB 脚本
├── Notebook
├── Skill 发布包
├── AI 整理后的 Markdown
└── 文献解析结果
```

它承担的是：

> **科研文件数据库和长期内容仓库**

普通成员不直接操作 NJU Box，而是通过 PLAB 网页访问。

## 2. 业务数据库

业务数据库负责保存系统运行信息：

```text
业务数据库
├── 用户与账号
├── 权限
├── 邀请码
├── 内容元数据
├── 上传者
├── 审核状态
├── 发布状态
├── 版本关系
├── NJU Box 文件位置
├── 任务状态
├── 通知
├── 日志
└── 反馈
```

NJU Box 和业务数据库共同构成系统的数据基础：

```text
NJU Box
负责“文件是什么、放在哪里”

业务数据库
负责“文件属于谁、处于什么状态、谁能访问”
```

## 3. 检索索引

检索索引保存：

* 文献切分片段
* 文本向量
* 关键词索引
* 文献与片段对应关系
* 检索排序信息

检索索引可以从 NJU Box 和业务数据库重新生成，因此它不是最终数据来源。

## 4. 模型服务

模型服务负责：

```text
模型服务
├── 文献摘要
├── 元数据辅助提取
├── 研究问题、方法和结果提取
├── 标签生成
├── 笔记整理
├── 多语言向量生成
└── Agent 回答
```

模型服务和网站独立运行。模型故障时：

* 网站仍可登录和浏览
* 已建立的索引仍可搜索
* 新任务进入等待队列
* Agent 暂停回答
* 模型恢复后继续处理

## 5. GitHub

GitHub 不再存放大量科研文件。

主要负责：

```text
GitHub
├── PLAB 平台源代码
├── Skill 源代码
├── Skill 测试
├── Prompt 和数据规范
├── GitHub Actions
└── 部署配置
```

# 九、系统核心业务流程

## 1. 文献流程

```text
成员上传 PDF
→ 文件保存到 NJU Box
→ 提取和补全文献信息
→ 检查重复和版本
→ 解析全文
→ 生成摘要和标签
→ 上传者审核
→ 上传者发布
→ 建立搜索索引
→ Agent 可以使用
```

## 2. 推导与笔记流程

```text
成员上传原始资料
→ 文件保存到 NJU Box
→ AI 整理为 Markdown
→ 标记疑似错误
→ 上传者审核
→ 发布
→ 进入检索
```

## 3. 代码流程

```text
成员上传脚本
→ 文件保存到 NJU Box
→ AI 提取功能和依赖
→ 上传者确认
→ 发布
→ 进入代码搜索
```

## 4. Skill 流程

```text
成员创建个人 Skill
→ 本地测试
→ 上传系统
→ 申请共享
→ 管理员审核
→ 发布版本
→ 成员下载并配置到 Codex
```

# 十、内容生命周期

所有科研内容统一经过以下生命周期：

```text
上传
→ 自动处理
→ 草稿
→ 上传者审核
→ 发布
→ 检索和使用
→ 修改形成新草稿
→ 发布新版本
→ 弃用、停用或删除
```

只有已发布内容：

* 可以被普通成员搜索
* 可以被 Agent 使用
* 可以作为课题组正式知识

# 十四、顶层设计原则

整个系统应遵循以下原则：

1. **原始资料永远保留。**
2. **AI 生成结果必须由上传者确认。**
3. **未发布内容不进入正式检索。**
4. **Agent 的结论必须可以追溯到来源。**
5. **NJU Box 保存内容，业务数据库管理状态。**
6. **检索索引必须可以重建。**
7. **普通成员不需要操作 GitHub 或 NJU Box。**
8. **Skill 必须有版本、依赖和测试说明。**
9. **管理员可以独立停用高风险模块。**
10. **先打通完整流程，再逐步增加高级能力。**
