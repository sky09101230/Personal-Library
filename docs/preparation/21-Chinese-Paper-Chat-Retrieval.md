# 中文论文问题的检索修复

日期：2026-09-30。无新增依赖，继续复用单篇 EvidenceCatalog、统一 Provider 和 SQLite 对话。

验收：中文“本工作工作在什么波段？网络结构是什么样的”能检索到英文原文，正常生成有引用的回答；改写失败仍有波段/架构等通用检索词回退，不增加外部科学事实。真正无匹配时说明本次检索限制，不能声称论文没有材料。输入只能许可实际送入的原文，不引用被截掉的部分。

根因：rewrite_query 把 LLMResult 当字典 .get，实际抛 AttributeError 并被吞掉；请求也没有 queries 输出合同，造成中文检索词与英文正文不匹配。截图 Parse 4 原文明确记载 0.4 THz、0.75 mm 和五层网络，旧检索的 literal hits 为零。

修复：明确查询改写 JSON 合同，解析 result.content，校验最多四条有限查询；仅用历史消解指代。常见中文科研术语提供英文搜索别名（不是答案或 Evidence）。去除英文疑问词/停用词，稳定排序不比较异构 locator 类型。上下文只装完整来源，过长条目跳过并继续尝试其余命中。改写请求最多 12 秒、无重试；Chat 回答请求最多 60 秒、无重试并限制 2048 输出 token，总调用保持在现有 120 秒 lease 内。英文问题无需额外改写调用。

回归涵盖实际 Provider 结果对象、复合中文提问的波段/结构两种来源、超时别名回退、问候无匹配和长条目不阻塞其余证据。真实验证仅保存在本地 Chat 数据库，不提交论文/密钥/完整模型响应。

验证：Parse 4 使用用户截图的原问题和本机配置 Provider，40.2 秒返回 supported 回答，包含 0.4 THz、五层衍射网络、8×8 cm 以及十个输出探测区域，各 claim 通过实际输入 allowlist 校验。该输入没有直接覆盖波长时，回答明确标注未直接提供，而非计算或猜测波长。文献处理模块 145/145 测试通过，OpenSpec strict 33/33、Django check 与无迁移检查通过。旧错误回答保留历史；新提问走修复后的检索。
